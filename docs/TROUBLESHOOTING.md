## 人机验证（CAPTCHA）与通知问题

### 问题 1：操作日志显示“检测到安全人机验证！已自动暂停任务”，如何处理？

**原因**：  
Fab.com 或 Epic 平台检测到高频请求，触发了真人安全防护机制（如 Cloudflare Turnstile、ArkoseLabs 或 hCaptcha）。

**解决步骤**：
1. **不要刷新主页面**：脚本已将当前任务安全保留在待办队列头部，并自动暂停了派发，避免更多账号风控。
2. **定位验证标签页**：在浏览器的标签页列表中，找到标题带有 **`⚠️【需验证】`** 前缀的后台标签页。
3. **完成验证**：切换到该标签页，按照页面提示（页面顶部会带有红色横幅）完成人机验证勾选或验证码交互。
4. **恢复执行**：验证完成后，回到 Fab 搜索主页面，点击控制台底部的 **「一键开刷」** 按钮，任务将立即恢复继续。

---

### 问题 2：在设定中点击“开启并测试”，未收到浏览器测试通知

**可能的原因**：
1. **站点通知权限被拒绝**：您可能在之前将 `fab.com` 的通知权限设置为了“禁止”。
2. **系统“专注模式”或“勿扰模式”已开启**：macOS 或 Windows 的系统勿扰模式开启时，会静默接收通知而不弹出横幅。
3. **浏览器系统级通知权限未开启**：在操作系统设置中，未允许浏览器（如 Chrome）发送通知。

**解决步骤**：
1. 点击浏览器地址栏左侧的 **网站设置图标**（锁形或调谐器图标），找到 **“通知” (Notifications)** 选项，将其更改为 **“允许” (Allow)**。
2. 检查操作系统设置：
   - **macOS**：进入「系统设置」->「通知」-> 找到「Google Chrome」（或您的浏览器）-> 确保勾选“允许通知”及“横幅”。
   - **Windows**：进入「系统设置」->「通知」-> 确保勾选开启浏览器的通知横幅。
3. 检查系统右上角是否开启了“专注/勿扰”模式。
4. 调整后回到 Fab Helper 控制台「设定」选项卡，再次点击 **「开启并测试」** 验证。

### 问题 3：点击收到的系统通知，没有自动跳转到验证标签页

**原因**：  
现代浏览器出于反点击劫持（Clickjacking）及跨标签页安全隔离策略，严格限制由后台未激活标签页发起的 `window.focus()` 抢占系统前台焦点的行为。

**应对方法**：  
通知正文中已明确标出提示：“*请切换到标题含【需验证】的标签页*”。请直接在浏览器的标签页栏中点击带有 **`⚠️【需验证】`** 的标签页即可。

## HTTP 429 限速问题

### 问题 4：频繁触发 429 限速且等待时间长

**可能的原因**：
1. 同时在多个浏览器窗口或标签页中开启了自动入库。
2. 网站当前的全局风控阈值处于收紧状态。

**解决方案**：
1. **保持单实例运行**：确保只在一个标签页中开启自动入库，关闭其他多余的 Fab 搜索标签页。
2. **依赖自动恢复**：脚本内置了随机抖动退避算法，当遇到 429 时会自动等待 40~60 秒，并在此后通过轻量级探测自动恢复，请耐心等待控制台显示 `✅ 恢复探测成功！`。

## 入库失败与重试问题

### 问题 5：面板显示“❌ 失败”数字增加，如何排查与解决？

**排查方法**：
1. 点击控制台顶部的 **「📄 复制日志」**，将日志粘贴到文本编辑器中，查看标记为 `❌ 任务失败` 或 `📋 任务失败详情` 的具体原因。
2. 常见原因分类：
   - **Bundle 结算受阻**：部分需零元结算的资产包若遇到条款未勾选或人机验证，会进入保护态。
   - **网络波动或接口暂态超时**：瞬时网络抖动导致未能及时获取确认。
3. **一键重试**：
   - 直接点击控制台右下角的 **「🔁 重试失败 (N)」** 按钮；
   - 脚本会将所有失败项目重新移入待办队列，并再次尝试执行入库；
   - 借助已打通的 API-First 与 DOM 自动回落混合机制，绝大部分重试项目均可顺利入库。

## 游标与浏览位置问题

### 问题 6：刷新页面后没有回到上一次浏览的商品位置

**解决步骤**：
1. 确认在控制台 **「设定」** 选项卡中开启了 **「记住瀑布流浏览位置」**。
2. 如果之前手动切换过排序方式（例如从“最新”切换到“按字母排序”），脚本为了防止跨排序游标混乱，会主动重置浏览位置记录，此为正常保护行为。
3. 如需重新从顶部开始浏览，可随时点击位置行右侧的 **🔄** 图标清空游标记录。

## 脚本未运行或面板未出现

### 问题 7：进入 Fab.com 后，右下角没有出现 Fab Helper 控制面板

**检查步骤**：
1. **确认页面处于搜索列表页**：控制台设计仅在商品搜索与列表聚合页面（包含 `is_free=1`）展开，在单个独立详情页中脚本会自动隐藏主控制台以避免干扰正常阅读。
2. **检查脚本管理器状态**：点击浏览器工具栏中的 Tampermonkey 图标，确认 Fab Helper 处于 **开启状态 (Enabled)**。
3. **检查版本更新**：确保已安装最新版本构建的 `dist/fab_helper.user.js`。
